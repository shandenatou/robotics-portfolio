# 评测口径

[返回首页](../README.md)

## 每个结果必须绑定什么

任务与环境版本、初始布局/seed 清单、模型与代码版本、checkpoint、训练数据范围、训练预算、推理参数、动作预测/执行长度、成功判定和超时规则。

保留成功数和分母，不能只写百分比。分别报告计划 episode 数、实际完成数、任务超时、基础设施错误和缺失记录；不要静默剔除失败来改善成功率，也不要把进程启动失败当作模型能力的直接测量。计数规则应在比较前确定。

## 不混用的指标

- rollout reward 与独立闭环成功率；
- 示范标签拟合 loss 与动作可执行性；
- 单任务 Clean/Randomized 设置与跨任务平均；
- 评测 episode 数、不同训练 seed 数与日志文件数；
- sample approximate KL 与其他 KL 估计口径；
- 文件的生成/迁移日期与个人参与项目的起止日期。

## 报告全部相关对照

同时保留 baseline、中间退化 checkpoint 和最终候选。若根据同一评测集挑选 checkpoint，应披露选择过程，并使用独立留出评测验证，避免将选优偏差解释为泛化收益。

例如 79/100 到 83/100 表示 +4 个百分点，不是 +4% 的相对提升。没有重复与不确定性分析时，不写“显著提升”或“稳定提升”。对于分层设置，先逐设置报告，再说明合计权重。

## 证据级别

1. 方案/配置：说明想做什么或默认如何设置，不证明运行完成。
2. 实现/测试源文件：说明已有代码，不证明所有测试已通过。
3. 汇总报告：可核对表述和算术，但需防止混合实验与丢失路径。
4. 原始评测产物：可复核 episode 计数和失败类型。
5. 独立复现：在锁定条件下重新运行并记录结果。

当前材料包括方案、配置、训练指标与含逐 episode 字段的评测汇总；LingBot 160 行是事后审阅集元数据，FastWAM 仍是估计计数。它们与原始传感器轨迹、独立复现有区别。[数据字段与来源](../data/experiments/README.md)。本次整理没有启动 GPU 实验。
